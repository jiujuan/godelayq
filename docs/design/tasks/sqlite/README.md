## 每张卡片的结构

1. 任务目标：一句话说明这张卡交付什么。
2. 背景与当前问题：为什么现在没有，缺了会怎样。
3. 要实现的功能：逐条列出，可测试。
4. 实现步骤：按顺序的操作。
5. 测试要求：单元测试、集成测试、手工测试分别做什么。
6. 完成标准（DoD）：全部满足才算完成。
7. 验收方式：可直接复制的命令和预期输出。
8. 不在本任务范围：容易被额外多做、但明确不做的事。
9. 风险与回滚：可能遇到的问题，以及出问题时怎么退回。
10. 实现记录：**执行时补写**，逐条记录与卡片的偏离及原因。

## 全卡共同的验证口径

- `go build ./...`、`go vet ./...`、`go test ./... -race` 必须通过。
- `gofmt -l` 在本仓库会因为行尾 CRLF 报出大量文件，结果不可用。要做格式检查时只对新增文件显式执行 `gofmt -w <file>`，不要按 `gofmt -l` 的输出判断是否合格。
- 改了 `core/config.go` 的配置键，必须同时改 `configs/config.example.yaml` 和本机 `configs/config.yaml`（后者被 `.gitignore` 排除），否则 `go test -run TestExampleConfigMatchesLocal ./core` 会失败（本机没有 `config.yaml` 时该测试是跳过而不是通过，记录时要分清）。
  另有两个机制容易混：YAML 里的未知键被拒来自 `UnmarshalExact`（按 `Config` 结构体字段判断，`core/config.go:605`）；`core/config.go:554-595` 的字符串列表只做 `BindEnv`，漏项不会报错、只会让该项无法用 `GODELAYQ_*` 覆盖。新增配置节两处都要处理。
- 依赖方向红线：`core` 与 `api` 都不许 import SQLite 驱动；驱动只出现在 `store/sqlite`。接口定义在消费方（`api`、`executor`），由 `store/sqlite` 隐式实现。
- 构造函数命名一律 `New*`（`Open` 属于既有例外名单）。
- 默认关闭是硬要求：`observability.enabled: false` 时不建文件、不订阅、不注入，行为与本系列之前完全一致。每张卡的 DoD 都要有一条用例守住这一点。
- 涉及前端的卡片：`cd web && npx vue-tsc --noEmit` 与 `npm run build` 必须通过。图标只用 lucide。
- 每张卡片一个提交（改动跨面大时可以按"新增文件 / 接线 / 测试"拆成 2-3 个提交），提交信息用 Conventional Commits，前缀按改动内容选 `feat` / `fix` / `test` / `docs` / `refactor`。
- 在共享 worktree 里不要直接 `git stash`；需要暂存时用带名字的 tag。
- 冒烟一律在系统临时目录里造独立的二进制 + 配置 + 数据目录，跑完删除；不得写入仓库的 `configs/config.yaml` 与 `data/`。
